# חברותא — מציאת חברותא ללימוד

אפליקציית Web בעברית למציאת חברותא, פרסום בקשות לימוד וניהול התאמות. הממשק מותאם למובייל ולכתיבה מימין לשמאל (RTL).

## סטטוס נוכחי

**זהו אב־טיפוס להדגמה בלבד, לא מערכת ייצור מאובטחת.** האתר זמין לצפייה, אך אין להשתמש בו עדיין לרישום קהילה אמיתית או לשמירת מידע אישי.

- האתר: https://efi770.github.io/-my-new-project/
- המאגר: https://github.com/EFI770/-my-new-project

## מה קיים באב־טיפוס

- ממשק עברי RTL ותצוגה מותאמת למובייל.
- מסכי הרשמה והתחברות להדגמה.
- פרופיל לימוד, נושאים, רמה, זמינות ופורמט לימוד.
- פרסום בקשות וחישוב ציון התאמה לפי נושא, רמה, זמני לימוד, תדירות ואופן לימוד.
- בקשות חיבור, חברותות, דיווחים וחסימות — בסביבת הדגמה מקומית.
- מסך ניהול לדוגמה.

## מגבלות מהותיות — לפני פיילוט

הנתונים נשמרים ב-localStorage בדפדפן. אין כרגע backend או מסד נתונים משותף. לכן משתמשים שונים, דפדפנים שונים ומכשירים שונים אינם חולקים מידע.

מסכי אימות אימייל, איפוס סיסמה ו-Google הם הדמיות בלבד. הם אינם שולחים הודעות ואינם מבצעים אימות מול ספק זהות. הרשאות הניהול נשמרות בצד הלקוח ואינן מאובטחות. משתמש בעל ידע טכני יכול לשנות נתונים בדפדפן.

קיימים נתוני משתמשים לדוגמה וקוד דמו בתוך קובץ JavaScript ציבורי. אין להתייחס לחשבונות או לפרטי הקשר המוצגים בדמו כנתונים אמיתיים, ואין להשתמש בסיסמאות הדוגמה בשום שירות אחר.

**אין להזין כרגע מידע אישי או רגיש של משתמשים אמיתיים.**

## בדיקות

נדרשת Node.js בגרסה 18 ומעלה. להרצת בדיקות:

```bash
npm test
```

הבדיקות מכסות את מבנה קובצי האתר, טעינת הממשק, מנגנון חסימת כניסה לחשבון לא מאומת, והיגיון בסיסי של ציון ההתאמה. הן עדיין אינן בדיקות דפדפן מקצה לקצה, בדיקות עומס או בדיקות אבטחה מלאות.

GitHub Actions מריץ את הבדיקות לפני פרסום האתר. כישלון בבדיקות אמור לעצור את הפרסום.

## שלב נדרש להפעלה אמיתית

לפני פיילוט עם אנשים אמיתיים יש להשלים ולבדוק:

1. **אימות אמיתי:** ספק זהות כגון Supabase Auth, אימות אימייל אמיתי, איפוס סיסמה ו-Google OAuth שמוגדרים כראוי.
2. **מסד נתונים משותף:** העברת משתמשים, פרופילים, בקשות, התאמות, דיווחים וחסימות מ-localStorage ל-backend.
3. **הרשאות שרת:** מדיניות RLS לכל טבלה, בדיקות הרשאות לכל פעולה, ותפקידי ניהול שאי אפשר להעניק דרך הדפדפן.
4. **הגנת מידע:** לא לשמור סיסמאות בעצמנו; לצמצם איסוף מידע, להגביל חשיפת פרטי קשר, ולהגדיר מדיניות פרטיות ומחיקה.
5. **בדיקות מלאות:** תרחישי הרשמה וכניסה, שני משתמשים במכשירים נפרדים, התאמות, אישור הדדי, חסימה, דיווח, מחיקה, נגישות, מובייל ואבטחה.
6. **השקה מבוקרת:** בדיקת גיבוי ושחזור, ניטור שגיאות, ותהליך לטיפול בדיווחים ופניות משתמשים.

חיבור backend אמיתי מחייב הקמת פרויקט ושמירת הגדרות/מפתחות מתאימים. אין להכניס מפתחות פרטיים או מפתחות שירות לקוד ציבורי.
